# FirstBite — Mapeamento de Concorrentes / Prior Art

Data de acesso: 2026-09-14. Ver `ECOSYSTEM.md` para o contexto completo sobre a Cookie Chain e a descoberta de que este projeto (FirstBite) muito provavelmente é uma submissão para o bounty do Superteam Earn **"Create an App on Cookie Chain"** (sponsor: Cookie Chain, prêmio US$ 1.000, 72 submissões registradas, vencedores anunciados em 28/09/2026 — fonte: https://superteam.fun/earn/listing/create-an-app-on-cookie-chain-app/).

**Aviso de método**: a rodada 1 (tabela logo abaixo) cobre o que foi encontrado via busca web e GitHub API em 2026-09-14, incluindo os Pull Requests visíveis no repositório oficial `cookiechain/superteam-hackathon-submissions` mais alguns achados adicionais de busca. Uma **rodada 2** (seção "Submissões adicionais investigadas (rodada 2)", mais abaixo) ampliou a cobertura para ≈ 47 de 72 submissões (≈ 65%) usando busca de código no GitHub como proxy de índice não oficial. **Mesmo assim, isso NÃO é a lista completa das 72 submissões do bounty** — ver a seção de rodada 2 para a contagem exata e as limitações do método. Tratar esta tabela como uma amostra ampla, mas não exaustiva.

## Submissões adicionais investigadas (rodada 2)

Data de acesso: 2026-09-14. Método desta rodada:

1. `gh pr list --repo cookiechain/superteam-hackathon-submissions --state all --limit 200` → **apenas 16 PRs no total** (15 já existentes + 1 novo, PR #16 "CookiePilot" de `simongonzalezdc`). Ou seja, **o repositório oficial nunca teve mais de 16 PRs visíveis** — a suposição inicial de que "57 de 72 não têm PR visível" está confirmada e é ainda mais extrema do que se pensava: apenas ~16/72 submissões (22%) passaram por esse repositório.
2. `apps.json` do repositório oficial (via `raw.githubusercontent.com`) tem **apenas 5 entradas curadas**: `cookie-mcp`, `crumbs`, `sprinkle`, `cookie-tab`, `cookiebot` — um registry oficial "vitrine", não uma lista de submissões.
3. `WebFetch` em `https://superteam.fun/earn/listing/create-an-app-on-cookie-chain-app/` confirmou o texto "72 SUBMISSIONS" e a data de anúncio dos vencedores (28/09/2026), mas a página é uma SPA que **não expõe a lista individual de submissões/participantes** — apenas 1 tentativa foi feita, como combinado, e o resultado é **NOT VERIFIED** para a lista completa.
4. Como a maioria das submissões não passa pelo repo oficial, a técnica mais produtiva foi busca de código no GitHub (`gh search code`) por strings quase obrigatórias em qualquer cApp real da Cookie Chain — o endpoint de RPC `cookiescan.io` e a frase exata do bounty "Create an App on Cookie Chain". Isso funciona como proxy de um "índice não oficial" das submissões, já que qualquer app real precisa apontar para esse RPC.

## Conclusão sobre originalidade do FirstBite (revisada após rodada 2)

Esta conclusão substitui a versão anterior, que se baseava em ~18 submissões mapeadas (25% do total). Com a rodada 2, a cobertura efetiva subiu para **≈ 47 de 72 submissões (≈ 65%)**, usando três métodos complementares: (a) os 16 PRs do repositório oficial, (b) as 5 entradas curadas do `apps.json`, e (c) busca de código no GitHub por strings quase obrigatórias em qualquer cApp real da Cookie Chain (`cookiescan.io`, a frase exata do bounty), que funcionou como um índice não oficial muito mais abrangente do que o repositório oficial sozinho.

1. **Continua não tendo sido encontrado, em nenhuma das ~47 submissões inspecionadas, um produto que combine os quatro elementos do FirstBite num único fluxo**: (a) link/QR gerado por um holder de COOK, (b) reivindicável por um destinatário desconhecido com 0 COOK, (c) sem ação prévia de bridge/faucet por parte de quem reivindica, (d) com a taxa da transação de claim patrocinada automaticamente. Isso vale tanto para a rodada 1 quanto para os 27 projetos novos da rodada 2.
2. **O achado mais próximo estruturalmente na rodada 2 foi Oven Mitt** (github.com/mandarwagh9/ovenmitt): cria uma carteira de sessão com teto de gasto, financiada e revogável, para um agente de IA. É o único projeto encontrado em qualquer rodada que "cria e financia uma carteira controlada sob regras para um terceiro operante" — mas o terceiro é um agente que age em nome do próprio dono já financiado, não um humano desconhecido e zerado reivindicando via link/QR; não há patrocínio de taxa do lado de quem recebe. **Não é uma sobreposição real, mas é o vizinho conceitual mais próximo já visto.**
3. Os elementos individuais do FirstBite continuam a ter prior art claro e disperso, agora com mais exemplos:
   - **Fee sponsorship on-chain**: **Arisan** (rodada 1), mais o padrão documentado pela Solana (Cookbook) e Blink Labs (ecossistema amplo). Nenhuma submissão nova da rodada 2 implementa patrocínio de taxa para um destinatário desconhecido.
   - **Link + QR para transação**: **Cookie Tab**, **Sprinkle** (rodada 1) e agora também **Cookie Ledger** (rodada 2) — todos no sentido pagamento (quem paga já tem saldo), nunca no sentido claim.
   - **Distribuição para múltiplos destinatários / airdrop (push)**: **Cookie Payouts**, **Crumbs** (WolfurX, rodada 1), e as variantes de "Crumbs"/"Cookie Jar"/"Cookie Crumb Jar" da rodada 2 — sempre push (remetente já conhece o destino) ou tip para um vault compartilhado, nunca pull-claim por um desconhecido.
   - **Validação externa do problema**: **Crumbs Portfolio** (paulandrew12, rodada 2) e **Cook-Incinerator** (rodada 2) confirmam, de fontes independentes, que "falta de COOK para gas" é uma fricção real e reconhecida no ecossistema — mas nenhum dos dois resolve isso para um destinatário zerado; o primeiro exige que o próprio usuário já tenha COOK, o segundo cobra uma taxa de 5% em vez de patrocinar.
4. **Risco residual**: ainda restam ~25 submissões (35%) nunca inspecionadas, e a técnica de busca por `cookiescan.io` tem limitações conhecidas (não pega repositórios privados até o prazo, nem projetos que não hard-codam essa string). O risco de existir 1 submissão adicional que replique o fluxo completo do FirstBite não pode ser descartado a 100%, mas caiu substancialmente: em ~47 amostras adicionais de escopo aberto — incluindo várias que tocam temas adjacentes (fee, jar, claim, airdrop, agent wallets) — nenhuma chegou perto de combinar os quatro elementos.
5. **Recomendação final**: o conceito do FirstBite pode ser mantido como está — a pesquisa não encontrou motivo para pivotar o mecanismo central. Ainda assim, dado que ~35% das submissões seguem não verificadas e que a colisão de nomes é comum neste bounty (4× "Cookie Pulse", 4× "CookiePilot", 3× "Cookie Jar", 3× "Crumbs", 2× "CookieForge"), o pitch do FirstBite deve **liderar explicitamente com o diferencial pull-based + zero-balance + fee sponsorship integrados em um único claim via link/QR**, citando por nome os concorrentes mais próximos (Arisan para sponsorship, Cookie Tab/Sprinkle para link+QR, Oven Mitt para "carteira financiada de terceiro sob regras") para demonstrar que o júri está lidando com uma combinação nova de partes conhecidas, e não com uma alegação vaga de ineditismo.
